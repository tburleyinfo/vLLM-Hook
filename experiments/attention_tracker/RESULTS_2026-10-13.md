# MLR-15 / MLR-40 — first GitHub Copilot Auto pilot

The experiment ran through the native `act` workflow on October 13, 2026.
Both conditions produced repository patches and notebooks. Neither candidate
reached Metal generation-time Q/K capture. CPU/Metal score parity is blocked.
This is an infrastructure and translation pilot, not evidence that graphs improve
translation.

## Frozen inputs and method

- Source: current MIA implementation at `3c4f6874cd007ca39fd76c40b8c481b573798cf3`.
- API: `MiaLLM`, `capture_qk`, `attn_tracker`; the obsolete `HookLLM` notebook API was excluded from the requested implementation.
- Translator: GitHub Copilot CLI `1.0.97`, Auto, provider-default reasoning. Both trials' recorded calls used `gpt-6-luna`.
- Source-only and source + draft Mermaid DAG started from identical disposable repositories. Exact prompts and hashes are retained.
- The graph is code-grounded and **not human-validated**. Copilot's current Free-plan model picker exposed only Auto; controlled mode rejects Auto.
- Both trials had the same verified `apply_patch` write tool plus create/edit/view/search tools. Shell and MCP tools were disabled; evaluation ran independently afterward.
- Shared inference model: `Qwen/Qwen2.5-3B-Instruct`, revision `aa8e72537993ba99e69dfaafa59ed015b17504d1`; dtype float32, layer 0/head 0, last-token Q, full-prompt K, `sum_normalize`, temperature 0, one generated token, prefix caching off.
- CPU evidence was reused only after matching source revision/archive, evaluator hash and every fixture setting. The raw log and origin/result hash are included.

## Observed results

| Condition | Candidate generation | Python syntax / notebook JSON | Metal fixture | CPU↔Metal comparison |
| --- | --- | --- | --- | --- |
| Source only | Patch + adapter + notebook + usage notes | Pass | Blocked before generation | Blocked |
| Source + draft source DAG | Patch + adapter + notebook + config + usage notes | Pass | Blocked before generation | Blocked |

CPU generation, Q/K capture, analyzer execution and structural checks passed.
The two CPU prompt scores were `0.12568315863609314` and `0.06351817399263382`.
Captured Q was `[2048]` per prompt; K was `[25, 256]` and `[33, 256]`, float32 and
finite. These are diagnostic head-0 scores, not an evaluation of injection detector
quality. The original MLR-53 OPT-125M fixture also passed separately; its scores
are not comparable to these Qwen scores.

The direct, unadapted MIA Metal preflight loaded the model but failed when
generation attempted hook installation: `require_v2_runner` rejects
`vllm_metal.v1.model_runner.MetalModelRunner`.

Both generated candidates assumed an in-process PyTorch model exposing forward
hooks. The installed vLLM-Metal runner does not expose that model through their
chosen interface, so both raised explicit unsupported-capture errors during
adapter initialization. No Metal score or parity claim was produced. The logs
also retain a PyTorch MPS allocator assertion during backend shutdown.

Generation took approximately 206 seconds for source-only and 209 seconds for
the graph condition. These two observations are not a performance benchmark.
The graph candidate generated an extra configuration/documentation artifact, but
that does not establish improved functional translation.

## What the pilot establishes

The branch contains a working local workflow for freezing inputs, building two
prompts, invoking Copilot, collecting separate patches, and applying a common
independent CPU/Metal fixture. Six protocol tests pass, including model-mismatch
rejection, execution requirements, finite-score checks, numerical tolerances,
prompt separation and CPU-baseline reuse.

It does not establish an executable MLR-15 Metal port, a human-validated G1
condition, a controlled fixed-model comparison, or full code equivalence.
Numerical tolerances remain provisional. Full notebook schema validation was not
run because `nbformat` was absent from the CPU environment; notebook JSON and
candidate Python syntax were checked.

## Next implementation boundary

MLR-15 needs a backend-specific capture/probe bridge inside the actual Metal
execution path. Inspect its MLX post-RoPE attention seam and request metadata;
preserve last-token query, complete prompt keys, GQA dimensions and request
ordering. A notebook or a generic PyTorch forward-hook wrapper cannot supply
that integration by itself.

Preserve these candidates unchanged as trial outputs. A subsequent target-context
or deterministic-CPG condition must be recorded separately. The primary controlled
comparison also needs a reviewed graph and a fixed-model Copilot account.
