# Changes 2026-02-20

This document summarizes the setup/runtime fixes implemented for vLLM-Metal + vLLM-Hook (`attntracker` path), including script, plugin, worker, and example updates.

## 1) New Setup and Launch Scripts

### Added
- `scripts/setup_attntracker_metal_env.sh`
- `scripts/run_attntracker_notebook.sh`

### Purpose
- Provide a repeatable setup where `vllm-metal` and `vllm_hook_plugins` are installed into the same virtual environment.
- Ensure notebooks run from the exact kernel tied to that environment.

### Key behavior
- Setup script runs `vllm-metal/install.sh` from the `vllm-metal` directory.
- Uses `vllm-metal/.venv-vllm-metal` as the environment source of truth.
- Installs:
  - `-r requirement.txt`
  - editable `vllm_hook_plugins`
  - `ipykernel`, `jupyterlab`
- Registers kernel `vllm-metal-attntracker`.
- Supports override via `VLLM_METAL_REPO`.

## 2) HookLLM Path and Environment Robustness

### Updated
- `vllm_hook_plugins/vllm_hook_plugins/hook_llm.py`

### Changes
- Default `download_dir` changed to `~/.cache/vllm_hook`.
- `download_dir` and `hook_dir` now use `expanduser` + `abspath`.
- Hook cache directory creation now targets resolved local writable paths.
- `LLM(download_dir=...)` now uses resolved absolute path.

### Why
- Fixes failures caused by hardcoded non-local paths and non-expanded `~`.

## 3) Metal Worker Selection Fix

### Updated
- `vllm_hook_plugins/vllm_hook_plugins/__init__.py`
- `vllm_hook_plugins/vllm_hook_plugins/hook_llm.py`

### Changes
- Plugin registration now selects Metal worker classes on macOS arm64 when `vllm_metal` is installed.
- `HookLLM` includes a direct Metal fallback override for:
  - `probe_hook_qk` -> `ProbeHookQKWorkerMetal`
  - `steer_hook_act` -> `SteerHookActWorkerMetal`

### Why
- Prevents accidental selection of CUDA/GPU worker classes on Apple Silicon, which produced `Not support device type: cpu`.

## 4) c10d/Distributed Bootstrap Mitigations

### Updated
- `vllm_hook_plugins/vllm_hook_plugins/hook_llm.py`
- `vllm_hook_plugins/vllm_hook_plugins/workers/metal/probe_hookqk_worker_metal.py`
- `vllm_hook_plugins/vllm_hook_plugins/workers/probe_hookqk_worker.py`

### Changes
- On Metal hosts, set defaults:
  - `VLLM_ENABLE_V1_MULTIPROCESSING=0`
  - `VLLM_HOST_IP=127.0.0.1`
  - `MASTER_ADDR=127.0.0.1`
  - `GLOO_SOCKET_IFNAME=lo0`
- Removed direct distributed rank query from probe workers:
  - replaced `parallel_state.get_tensor_model_parallel_rank()` with env-based `VLLM_TP_RANK` defaulting to `0`.

### Why
- Reduces hangs/retries from gloo binding to non-loopback interfaces (for example VPN/network-assigned `10.x.x.x` addresses).

## 7) Operational Findings from Runtime Testing

- On 8GB unified memory, `ibm-granite/granite-3.1-8b-instruct` is not feasible for this path.
- Confirmed failure mode from `vllm_metal` auto memory check:
  - model footprint exceeds available memory (`auto` memory fraction infeasible).
- Recommended for 8GB validation:
  - `Qwen/Qwen2.5-0.5B-Instruct`
  - `Qwen/Qwen2-1.5B-Instruct`
